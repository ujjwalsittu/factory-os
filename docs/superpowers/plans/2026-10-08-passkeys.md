# Optional Passkeys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let existing users enroll and sign in with personal passkeys while preserving local TOTP, recovery and current authorization.

**Architecture:** Use the version-matched native passkey plugin and its actual WebAuthn verifier, with fixed configuration and application-owned transactional consent/credential/evidence. A request-scoped adapter boundary keeps native direct writes and store SQL on the same PostgreSQL transaction; private provenance preserves the real TOTP challenge and rejects provisional authority. The web makes explicit browser ceremony requests so proof headers reach both native endpoints.

**Tech Stack:** TypeScript, NestJS, Better Auth 1.7.7, `@better-auth/passkey@1.7.7`, Drizzle/PostgreSQL 16, Next.js, Playwright and the native plugin's SimpleWebAuthn 13 family.

**Spec:** [Approved design](../specs/2026-10-07-passkeys-design.md), accepted decision 045. Written spec approved by user Continue on 2026-10-08; this plan awaits review.

**Execution method:** Native inline, already selected by the user. No per-task implementer/reviewer agents. One fresh independent final reviewer after all verification, one Critical/Important correction pass; no second review. The header offers general methods; this selection controls execution.

## Global Constraints

- Optional existing accounts only; disabled by default. No account creation/merging, password removal, administrator bypass, tenant/role grant or TOTP replacement.
- `PASSKEY_ENABLED=false`; enabled configuration requires `PASSKEY_RP_ID`, exact `PASSKEY_ALLOWED_ORIGINS` (default canonical `WEB_ORIGIN`), and `PASSKEY_MAX_PER_USER` default 10, integer 1–20. RP name FactoryOS; production HTTPS, local HTTP only explicit `localhost` ports/RP `localhost`. Core trusted-origin/CSRF checks still apply; no wildcard, request-Origin fallback or automatic extra-origin inheritance.
- Registration: `attestation: none`, discoverable credential and required user verification. Both native verification callbacks reject verified results without UV before persistence/session creation; client options alone are insufficient.
- Label trim/length 1–80; live management session age strictly below 300 seconds plus password confirmation and completed existing MFA. Action/challenge lifetime no more than 300 seconds; database time after waits. Changing labels cannot alter identity.
- Credentials have globally unique canonical ID and immutable owner/RP/public key/server-generated user handle. Synced zero counters remain supported under native verifier semantics. Only safe owned summaries leave the API.
- TOTP-enabled users retain existing TOTP/backup/trusted-device policy; private pending sessions never authorize application/native security access. No UV-to-TOTP shortcut. Password change/reset invalidates old pending provenance through a private keyed credential-version digest.
- Removal revokes pending/completed sessions sourced from that credential, including the current one when applicable; disabled/old-RP credentials remain manageable through local proof. Configuration disable alone preserves completed-session expiry/revocation.
- Password/backup recovery remains; password reset does not delete passkeys. No live SMTP/provider/credential/device enrollment, secrets, shared data reset or book activation during implementation fixtures.
- Pin new direct dependencies: API `@better-auth/passkey@1.7.7` and `@better-auth/core@1.7.7` for exported context APIs; web `@simplewebauthn/browser@13.3.0` for explicit ceremony calls. No auth/Next/Drizzle upgrades. Verify peer resolution and use inferred native callback types rather than importing undeclared transitive dependencies. Existing two-factor client remains.
- Merge SSO final corrections before product work. Main now includes manufacturing decision044/migration0027 in73de072; the planning branch incorporates that main unchanged. Generate additive SQL from the latest live journal; never reserve/overwrite a migration number or prior SQL. Merge a standalone passkeys claim PR before implementation; no direct main push, green CI before merge.
- Pinned workspace runtime: Node24.19 / pnpm10.28 via `/workspace/.factoryos-tools/node_modules/.bin` when using this cloud workspace. Every fixture defaults API4000/web3000 and honors `API`, `WEB_ORIGIN`, `WEB_URL`; disposable DB/runtime fixtures run sequentially on shared ports.

## Review Focus

1. Native convenience-client options GET omits custom proof/return headers; both explicit browser requests must carry the correct current-session proof. Test in Task6.
2. A credential created under an old RP must remain removable while the feature is disabled or RP changes; it must not sign in under the new RP. Test in Tasks3/7.
3. A password reset while passkey TOTP waits must invalidate the old private version without deleting enrolled credentials or waiving MFA. Test in Task5.
4. Returning a native error response or failing required evidence must not commit authority or emit a usable session cookie; evidence belongs inside the SQL transaction, not a queued after-commit hook. Test in Tasks2/4.
5. An already signed-in browser or held response from a previous account must not silently switch users, display their keys or reuse their action; valid native renewal cookies and SSO deletion authority must survive composition. Test in Tasks4/6/8.

# GL Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Establish reconciled opening books per entity and post new operational activity to an immutable, balanced INR general ledger with accountant-facing journals and reports.

**Architecture:** Pure decimal-string builders produce accounting lines. A transaction-aware GL service validates and persists them inside existing stock/invoice transactions. Entity activation establishes an opening snapshot without replaying history; all operational posting paths share its entity lock.

**Tech Stack:** Existing pnpm/Turborepo, TypeScript, NestJS, Drizzle/PostgreSQL, `Dec`, Zod, Next.js, TanStack Query, `@factoryos/ui`, Vitest and Playwright. No new production dependency.

**Spec:** `docs/superpowers/specs/2026-10-05-gl-core-design.md` (approved in chat).

## Global Constraints

- Existing operational history remains intact and is not reconstructed into historical journals.
- Activation uses the current business date in Asia/Kolkata; store the exact activation timestamp and a source snapshot.
- Store INR journal amounts at six fractional digits to preserve FIFO reconciliation; use decimal strings at API boundaries.
- Posted vouchers and GL entries cannot be edited or deleted; cancellation appends exact reversals.
- A failed accounting check rolls back the entire operation.
- Entity activation is explicit; migration never activates accounting or chooses a production cut-over date.
- Preserve existing stock cancellation guards, permissions, ownership rules and decisions 008/018/019/023/024/026/028/030.
- No product code before plan review; no accounting activation on shared dev/production during development.
- Customer/supplier settlement workflows remain the follow-on AR/AP task in STATUS, not an implicit addition to this implementation.
- Do not push an intermediate migration or partial posting integration to the auto-deploy branch. Task commits remain local until full validation.

## Review Focus

1. A document submitted during opening review must invalidate the snapshot; Task 3 tests concurrent activation/posting.
2. A foreign invoice billed partially against several receipts must clear only original base cost; Task 5 tests allocations and negative FX/price differences.
3. Cancellation after mappings change must reverse old accounts/amounts, not rebuild a voucher; Tasks 2/6 test immutable reversal snapshots.
4. Non-creditable acquisition tax after stock has been consumed must split cost correctly and retain movement guards; Task 4 tests on-hand and issued shares.
5. Read-only or entity-scoped users must not change another entity's openings/accounts through supplied IDs; Tasks 3/7 test server and browser permissions.

## File and interface map

- `packages/core/src/accounting.ts`: shared `AccountingLine`, `PostingPlan`, exact balance/variance and reversal primitives; exported by `packages/core/src/index.ts`.
- `packages/db/src/schema/accounting.ts`: groups, accounts, settings, opening worksheets/details, journal drafts, append-only GL/dispositions and receipt invoice allocations; exported by schema/index.ts. Generate the next migration under `packages/db/drizzle/` from the schema; inspect SQL rather than hand-editing snapshots.
- `apps/api/src/modules/accounting/`: `accounting-lock.ts`, `chart.ts`, `gl-posting.service.ts`, `opening.service.ts`, `accounting.controller.ts`, `reports.controller.ts`, `operational-postings.ts`, `receipt-allocation.service.ts`, `acquisition-cost.service.ts`. Keep each responsibility separate.
- Existing `stock-posting.service.ts`, `buying.controller.ts`, `selling.controller.ts`, `landed-cost.controller.ts`: small transactional integration calls; register services/controllers in `app.module.ts` without dependency cycles.
- `apps/web/src/lib/accounting.ts`, `components/accounting-journal-form.tsx`, `app/app/accounts/`: setup, chart, journals/new/[id], day-book, ledger and trial-balance pages. Register shell and palette actions.
- New tests: `packages/core/src/accounting.test.ts`, `apps/api/scripts/smoke-accounting.sh`, `apps/api/scripts/smoke-accounting-concurrency.mjs`, `apps/web/e2e/accounting.mjs`.

Shared types: `AccountingLine = { accountId: string; debit: string; credit: string; partyId?: string; billReference?: string; gstRegistrationId?: string }`; `PostingPlan = { lines: AccountingLine[]; disposition: 'posted' | 'no_value_change' }`; `SourceRef = { type: string; id: string; purpose: string; number?: string }`. Contextual currency/rate/narration fields belong on voucher inputs; source builders resolve account mappings before calling the GL writer. All monetary strings accept at most six fractional digits at accounting boundaries.
